  How the starter works

  - Agent class: ChatAgent in src/server.ts:14. It extends AIChatAgent from
    @cloudflare/ai-chat, which builds on Agent from agents. Each agent instance
    is a Durable Object backed by SQLite: wrangler.jsonc binds it with
    new_sqlite_classes: ["ChatAgent"].
  - Routing: the Worker's fetch calls routeAgentRequest, which maps
    /agents/<class>/<instance-name> to a Durable Object instance. wrangler.jsonc
    sends /agents/* to the Worker first; everything else is served as the
    single-page app from public/.
  - Message flow:
    a. app.tsx:284 calls useAgent({ agent: "ChatAgent" }) with no name, so every
       browser connects to the same instance (default) over a WebSocket.
    b. useAgentChat({ agent }) sends user messages over that socket.
    c. On the server, AIChatAgent saves the message and calls onChatMessage().
    d. That runs streamText against Workers AI (Llama 3.3), using this.messages
       plus the tools.
    e. The reply streams back to the browser as toUIMessageStreamResponse().
  - Where state is stored: chat history lives in the Durable Object's SQLite,
    managed by AIChatAgent and capped at maxPersistedMessages = 100. MCP server
    connections are also kept per instance. The starter doesn't use the general
    this.state/setState mechanism at all.

  What you get
  - Notes panel: on the right of each incident page, always visible on a laptop.
    On a narrow screen it's hidden behind a "Notes (n)" button in the header.
  - Add: type in the box and press Enter or +. New notes start as open.
  - Rule out: the ⊗ button moves a note to "Ruled out" and strikes it through.
    The ↺ button puts it back to open, in case you misclick.
  - Delete: the trash button removes a note.
  - Saved per incident: notes are kept with each incident, survive reloads, and
    update live in every open tab.
  - What the AI sees: before each reply, the AI gets the current open and
    ruled-out lists. It's told never to suggest a ruled-out cause again, to
    focus on the open ones, and to trust the notes over older chat messages.
  - Simple safeguards: only the add, rule-out and delete actions can change
    notes. A browser can't overwrite them directly. Empty notes are rejected,
    and there's a cap of 50 notes of 500 characters each, so the AI's context
    stays small.

  What I tested, end to end against a fresh incident:
  - I added two notes, ruled one out and deleted one. Each change showed up
    straight away in a second connection.
  - An empty note and a direct overwrite from the browser were both rejected.
  - I added "Disk full on primary DB" as a note, marked it ruled out, then sent
    an alert saying "disk usage 98%". The reply said: "since 'Disk full on 
    primary DB' is already ruled out, it's possible that the issue is related to
    disk I/O or contention rather than absolute capacity". So the model did see
    the ruled-out note and steered away from it. It didn't bring up the
    remaining open note on its own, though. Llama follows the "focus on open
    hypotheses" rule loosely.
  - Typecheck and lint pass.

  How to test it yourself
  1. Run npm run dev and open /incident/notes-demo.
  2. Add "Disk full on primary DB" and "Bad deploy of orders service", then rule
     out the disk one.
  3. In the chat, send: "Alert: orders-db p99 900ms, disk 98%. Most likely 
     cause?" The reply should not call the full disk the cause. It may mention
     it was ruled out.
  4. Put the disk note back to open and ask again. Now it's fair game.
  5. Reload the page: the notes should still be there. Open the same incident in
     a second tab and add a note: it should appear in both. Open a different
     incident: its panel should be empty.
  6. Delete a note and check it disappears in both tabs.

  About deploying: no wrangler or migration changes are needed. The notes are
  stored in each incident's existing storage, and incidents you already created
  will start with an empty notes list.

  Once you've committed, the last step is optional: letting the model add or
  rule out notes itself through tools. Given how loosely Llama followed the
  instructions here, I'd test that carefully before relying on it.
